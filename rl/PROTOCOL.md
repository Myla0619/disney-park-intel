# Park Agent protocol and retraining gate / 调用协议与重训门禁

This is a text-based, sequential protocol, not OpenAI native function calling or Anthropic `tool_use`.
这是顺序执行的文本协议，不能把 Anthropic 客户端仅替换 URL 后直接接入。

## 1. Message ownership / 消息归属

| Producer | Chat role | Content |
|---|---|---|
| Application | system | Frozen park, date, tool descriptions and JSON schemas |
| Visitor | user | Question |
| Model | assistant | Exactly one closed think, then one tool_call OR nonempty answer |
| Tool executor | user | One tool_response containing a result envelope |

Example assistant message:

```text
<think>先查排队</think><tool_call>{"name":"get_wait_times","arguments":{"park_id":"shanghai","ride_id":"tron"}}</tool_call>
```

Example executor message (never generated by the model):

```text
<tool_response>{"ok":true,"result":{"waitMinutes":75}}</tool_response>
```

Next assistant message:

```text
<think>已有数据</think><answer>工具显示排队约75分钟。</answer>
```

Missing/null/array arguments, mixed answer+call, multiple calls, trailing prose, unclosed tags and assistant-produced tool_response are rejected. No execution of a first call extracted from malformed text. Empty answers do not end an episode.

旧 GRPO 的兼容选项 `allowLegacyAssistantCall: true` 只用于助手输出的推理解析，默认关闭；只修复完整的 think+单个旧调用标签，保留 raw 和格式错误。训练、原生评测禁止开启，不修改历史成绩或真实工具返回。

## 2. Tool contract / 工具清单

`env/tools.ts` is the source; `train/tool-contract.json` is its generated snapshot. Run `npx tsx rl/train/export_contract.ts --check` to detect drift. `env/contract-check.ts` additionally compares it with the live in-process registry. Read the JSON artifact for exact nested fields, enums and constraints; do not maintain another hand-written parameter list.

| Tool | Required arguments | Optional arguments |
|---|---|---|
| get_wait_times | park_id | ride_id |
| search_reviews | park_id, target_id, target_type, query | top_k (integer 1–20) |
| plan_itinerary | park_id | profile, route_profile, start_area, avoid_rides |
| get_spot_info | park_id, spot_id, spot_type | current_area |
| get_show_schedule | park_id | — |
| get_ll_pricing | — | package_id |
| walk_time | park_id, from_area, to_area | mobility_needs |
| check_constraints | park_id, itinerary | profile |
| get_weather | park_id | date |

参数不自动做字符串/数字/布尔转换；未知顶层字段拒绝。`target_type` 为 ride/restaurant；`spot_type` 为 ride/photo/restaurant/shop。ID 不是显示名称。项目查询限定在指定 park；区域存在性由执行层检查。profile 有独立嵌套类型/枚举约束，不能覆盖 park_id。部分 schema 合法值仍可能不存在，必须执行工具才能确认。

`plan_itinerary.result.items` 保留完整原始行程字段（包括 itemId/endTime），可以直接传给 `check_constraints.itinerary`，使用同一 profile。空行程、非法时间、负时长和非法孩子身高不能作为约束通过。

## 3. Transport, failures and serving / 调用方法

Local executor: `callTool(name, arguments, {mode: "sandbox", snapshotAt: "..."})`.

HTTP executor: POST `/call` with `{"tool":"get_wait_times","args":{"park_id":"shanghai"},"mode":"sandbox","snapshot_at":"..."}`. Notice wire keys are tool/args, model keys are name/arguments. Success is `{"ok":true,"result":...}`; tool failures are HTTP 200 with `{"ok":false,"error":"..."}`. Malformed request envelopes use 400. HTTP client validates status and result envelope. Tool exceptions become feedback, not unhandled rollout crashes. Model HTTP requests abort after 120s, tool HTTP requests after 60s; the episode also races in-flight work against its remaining deadline. In-process Promise cancellation cannot stop arbitrary user-supplied code already running.

环境服务和 vLLM 启动脚本默认仅监听 127.0.0.1。通过 SSH tunnel 访问，不把无鉴权的 `/call` 或 `/reward` 暴露公网。LLM URL 应包含 `/v1`；客户端追加 `/chat/completions`。部署前验证 tokenizer/chat template/EOS、模型别名、原生输出协议及上下文预算。

## 4. What the metrics mean / 评分不能混用

Historical first-step evaluation counts protocol-valid expected tool names, not argument-value correctness, actual execution, or completed tasks. Its raw outputs and original scores remain unchanged. Offline label normalization is a separate diagnostic only.

New GRPO trial uses `reward_v2.py`: malformed output/unknown tool/schema-invalid arguments = 0; valid but wrong tool = 0.1; right tool = 0.5 plus up to 0.5 for matching audited reference argument keys. Missing reference labels stop training. Reference-key matching does not prove semantic or execution success; reasonable alternative tools/arguments need reviewed multi-label support before a larger run. No-tool answers receive only 0.2 format credit, not a semantic quality score. They are retained for regression testing; this trial does not optimize their answer quality.

旧单步奖励中的虚构执行成功、恒定约束满分和“随便调一个工具就得到答案分”已删除。多轮 TS 奖励仍是另一套启发式评估，不与单步 v2 分数比较。veRL 桥接必须带可信完整轨迹并匹配当前 completion，服务故障要停止，不再静默计模型零分；尚需安装版本对应的真实集成测试，不作为此次 TRL 小试验入口。

## 5. Required preflight before renting/running / 开跑前必须完成

1. Copy and hash old base, SFT adapter, raw evaluations and datasets; never overwrite/delete the old instance first.
2. Run all CPU checks below. Export a frozen full system prompt with park and explicit date. Review all training reference tool/argument labels; run `python3 rl/train/preflight.py DATA --eval-set EVAL` for duplicates and exact overlap. This is not a semantic leakage detector.
3. Old remote training data is not present in this clone: audit it on the new machine. Validate every SFT assistant target strictly; preserve actual tool responses as user messages. Existing SFT trainer builds full transcript text; assistant-only loss masking is NOT yet verified. Do not rerun SFT unchanged or assume it masks tool/user tokens.
4. Pin actual installed torch/transformers/peft/trl/bitsandbytes versions. Confirm base/SFT adapter compatibility, trainable LoRA parameters, finite loss/gradients, KL/reference behavior and template tokenization on GPU. Do not install arbitrary latest versions mid-experiment.
5. Tokenize the complete frozen prompt; reject truncation. Use the same prompt and decoder for baseline and candidate evaluation. Freeze sandbox snapshot/date, not today's default. Weather sandbox output is synthetic; live weather is not implemented. Shows may be snapshot/default; prices are static. None are evidence of live coverage.
6. Use a fresh `GRPO_OUTPUT_DIR` whose existing parent has >=10 GiB free; set all model/cache/tmp locations deliberately. The trainer checks space before starting and at step/save boundaries; this is not a reservation and cannot prevent another process filling the disk during a step. Limit retained checkpoints to two; never auto-delete unrelated files.
7. Only after review set `GRPO_PREFLIGHT_APPROVED=1`. Start from SFT. Default `GRPO_MAX_STEPS=30`; save every 10 steps. Run small GPU inference/gradient tests first. Increase run length only after a reviewed improvement, not a higher training reward alone.
8. Evaluate protocol, tool name, full arguments, real sandbox execution and final answer separately. Keep current 94 cases for regression; add an independently held-out set. Do not tune repeatedly on the final test set.
